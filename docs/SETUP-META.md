# ربط واتساب — إشعارات التجّار

> **تغيّر الدور:** لم تعد المنصة ترسل رموز تحقق — الدخول بريد وكلمة مرور
> من النظام الموحد. واتساب هنا لإشعارات التاجر فقط (طلب جديد، تذكير
> اشتراك). وما يذكره هذا الدليل عن قالب `otp_ar` وفئة Authentication
> ورمز التحقق تاريخيٌّ: الرسائل الحرّة تكفي داخل نافذة ٢٤ ساعة، وقالب
> معتمد (Utility) يلزم فقط لو أردت إيصال التذكير بعد صمت طويل.

الكود جاهز ومختبَر. ما تبقّى إعدادات داخل لوحة Meta لا يمكن إنجازها برمجياً.

الإرسال في الباكند الموحّد (`src/modules/notify/merchant-notifier.service.ts`)،
ويُضبط بالبيئة: `NOTIFY_CHANNELS=console,whatsapp` و`META_TOKEN` و`WA_PHONE_ID`
و`META_APP_SECRET` (اختياري، لـ`appsecret_proof`) و`WA_API_VERSION` (افتراضيًا v21.0).
القناة الفعّالة تُطبع في سجل الإقلاع («إشعارات التجّار: …»)، وخطأ Meta يُسجَّل
مع تلميح عن سببه.

> نُقل هذا الدليل من مشروع واجهة المتاجر بعد انتقال الإشعارات إلى الباكند؛ أداة
> `check:wa` القديمة لم تُنقل، والفحص اليوم بطلب تجريبي ومراقبة السجل.

## ما تحقّق فعلاً

| البند | الحالة |
|---|---|
| الرمز (Access Token) | ✅ رمز **مستخدم نظام دائم** (`expires_at: 0`) — لا ينتهي |
| صلاحيات الرمز | ✅ `whatsapp_business_messaging` · `whatsapp_business_management` · `business_management` |
| سرّ التطبيق | ✅ يعمل — `appsecret_proof` مقبول من Graph API |
| مراجعة الحساب | ✅ `APPROVED` |
| اسم العرض | ✅ `AVAILABLE_WITHOUT_REVIEW` |
| الرقم | ✅ `+967 739 008 083` |

## ما يمنع الإرسال الآن

### ١. الرقم على On-Premise API لا Cloud API — **العائق الأساسي**

```
platform_type: ON_PREMISE
status:        DISCONNECTED
```

وهذا ما أكّده الخطأ الحقيقي من Meta عند أول محاولة إرسال:

```
(#133010) Account not registered
```

On-Premise API واجهة قديمة أوقفت Meta دعمها، وتتطلّب خادماً خاصاً بها.
المشروع يستخدم **Cloud API** — وهي المسار المدعوم، ولا تحتاج بنية تحتية إضافية.

**الحل:** في *WhatsApp Manager ← إعدادات الرقم* اختر **Register** لتسجيل الرقم
على Cloud API. ستحتاج رمز PIN من ٦ أرقام (رمز التحقق بخطوتين). بعدها تصبح
الحالة `CONNECTED` و`platform_type: CLOUD_API`.

> ⚠️ الرقم `+967 739 008 083` هو رقمك الشخصي على واتساب. تسجيله على
> Cloud API **ينقله بالكامل إلى الـAPI** ويُخرجه من تطبيق واتساب العادي على
> الجوال. استخدم رقماً مخصّصاً للمنصة إن كنت تستعمل هذا الرقم شخصياً —
> الرجوع ممكن لكنه ليس فورياً.

### ٢. لا توجد قوالب رسائل إطلاقاً

الحساب يعيد `message_templates: []` — أي أن `otp_ar` غير موجود، ولا غيره.
رموز التحقق **لا تُرسل إلا بقالب معتمد**؛ الرسائل الحرّة تعمل فقط داخل
نافذة ٢٤ ساعة بعد أن يراسلك العميل.

**الحل:** أنشئ قالباً من *WhatsApp Manager ← Message Templates*:

| الحقل | القيمة |
|---|---|
| الاسم | `otp_ar` |
| الفئة | **Authentication** (لا Marketing ولا Utility) |
| اللغة | العربية `ar` |
| المتغيّرات | متغيّر واحد `{{1}}` = الرمز |
| الزر | Copy code |

الاعتماد يستغرق من دقائق إلى ٢٤ ساعة. لو اخترت اسماً آخر غيّر
القالب في لوحة Meta فقط؛ الكود يرسل حالياً رسائل حرّة.

### ٣. الحساب التجاري غير موثّق (لاحقاً، لا يمنع الإطلاق)

```
business_verification_status: not_verified
```

بدون التوثيق يبقى حدّ الإرسال **٢٥٠ محادثة/٢٤ ساعة**. يكفي للبداية،
لكن أنجزه قبل النمو — التوثيق يستغرق أياماً.

## الـWebhook

الوجهة موجودة ومختبَرة (١٧ فحصاً):

```
/api/webhooks/whatsapp
```

في *لوحة التطبيق ← WhatsApp ← Configuration*:

| الحقل | القيمة |
|---|---|
| Callback URL | `https://rviosstore.com/api/webhooks/whatsapp` |
| Verify token | نفس قيمة `WA_VERIFY_TOKEN` |
| Subscribe to | `messages` |

ثم اضغط **Verify and save**.

يجب أن يكون العنوان **علنياً وبـHTTPS** — لن يقبل Meta عنوان `localhost`.
للتجربة محلياً استخدم نفقاً (`cloudflared` أو `ngrok`).

كل طلب وارد يُرفض ما لم يحمل توقيع `X-Hub-Signature-256` صحيحاً محسوباً
بسرّ التطبيق، والمقارنة بزمن ثابت.

**ما يفعله الـWebhook:** يسجّل حالة كل رسالة (`sent → delivered → read`
أو `failed`) في جدول `wa_messages`. هذا يجيب على السؤال الذي لا تجيب عنه
استجابة الإرسال: نجاح النداء يعني أن Meta **قبِلت** الطلب، لا أن التاجر
**رأى** الرمز. نسبة الوصول تظهر في لوحة Meta (Insights).

## سلسلة القنوات

```env
NOTIFY_CHANNELS=whatsapp,console
```

تُجرَّب بالترتيب حتى تنجح واحدة، فعطل قناة لا يُسقط الإشعار كله.

`console` الآن شبكة أمان مؤقتة تُبقي التسجيل يعمل بينما الرقم قيد النقل.
**بعد اكتمال الخطوتين ١ و٢ أعدها إلى `whatsapp` وحدها** — وإلا ظلّ الفشل
مخفياً خلف قناة احتياطية تطبع الإشعار في السجل بدل إيصاله للتاجر.

عند توفّر بوابة SMS محلية اجعلها البديل الحقيقي: `whatsapp,sms`.

## المفاتيح

كلها في `.env` وهو مستثنى من Git. لا يوجد أي مفتاح داخل الكود.

| المفتاح | الغرض |
|---|---|
| `META_TOKEN` | رمز الوصول الدائم |
| `WA_PHONE_ID` | معرّف **الرقم** — `112922571910590` |
| `WA_WABA_ID` | معرّف **الحساب** — `131769083345172` |
| `META_APP_SECRET` | توقيع الطلبات والتحقق من الـWebhook |
| `WA_VERIFY_TOKEN` | تحدّي تفعيل الـWebhook |

> **انتبه:** المعرّفان متجاوران في اللوحة ويسهل الخلط بينهما. الخلط لا
> يظهر إلا عند أول إرسال فاشل، لأن عقدة الحساب تردّ `200` بلا حقول.
> سجل الباكند يكشفه صراحةً مع رمز خطأ Meta.

## عند التبديل إلى الإنتاج

```env
NODE_ENV=production
NOTIFY_CHANNELS=whatsapp
UNIFIED_API_URL=<عنوان الباكند الموحد>
UNIFIED_SERVICE_EMAIL=<حساب خدمة الفوترة>
UNIFIED_SERVICE_PASSWORD=<كلمة مروره>
VISIT_SALT=<عشوائي ثابت>
PUBLIC_URL=https://rviosstore.com
```

الإقلاع يتوقّف إن غاب `UNIFIED_API_URL` أو حساب الخدمة. واتساب هنا لإشعارات
التاجر (التذكيرات والطلبات) — الدخول بريد وكلمة مرور لا رمز واتساب.

توليد قيمة عشوائية:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
